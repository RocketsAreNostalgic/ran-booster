## Invariants frozen before production edits

- Presentation never gates public installation, management, import or credentials. Existing operation authority/integrity checks remain authoritative.
- One non-autoloaded site option, `ran_booster_overview_presentation`, stores only `dashboard` or `onboarding`. Invalid/missing means automatic. No GET writes, user metadata, completion/history flag or configuration reset.
- Explicit choices win. Confirmed installed managed records count regardless of activation or Disabled update policy. Installed files, Preview and uncertain adoption are not management.
- Each package repository is read once. A failure leaves that type unknown, never zero; completeness is independent of positive known records.
- Existing source cannot prove lifetime first use. Empty current inventories plus empty retained Activity also describe previous use, pruning, reset or loss. Database activation exposes no reliable later-request first-use fact. Automatic unproven-empty uses the accepted neutral dashboard and Return opens guidance. This cannot prove automatic first-use onboarding and must remain an explicit delivery limitation unless the owner revises the evidence constraint.
- No recovery scans, remote checks or credential-document reads for summaries. Existing protected storage inspection/result is captured once and reused. Storage recovery remains solely in its operational home.
- Admission is not checked access. Without current identity-bound evidence, access and credential expiry are unknown with provider-management links. Observations alone cannot establish a current credential census.
- Activity uses the existing bounded query with limit five. Unavailable differs from available-empty. Only safe projected event fields reach the view.
- Site options remain scoped to the current supported single site. Existing multisite refusal remains unchanged; no network-support claim.

## Expiry remediation contract (before production edits)

Independent review of the opened PR at `a78e30635b6784f9f8ee908bf151c426e2948000` reproduced a required correction: the ordinary administrator request already captures actionable, current-profile-bound expiry facts for its existing notice, while Overview unconditionally reports unknown. The regression uses the real notice/reminder flow and the actual Overview view; before the fix the notice renders a two-day expiry and Overview omits both its attention item and credential while claiming unknown.

Reuse the already captured request-local notice snapshot through a pure cached projection. It must never call `snapshot()`/`affected()`, enumerate credentials or decrypt storage when the cache is absent. Recheck administrator authority and login before returning safe fields. Return `status` (`captured`, `unknown` or `unavailable`), nullable `total` and at most five `items`; retain truthful limited reminder coverage, including captured-empty. Each item contains only provider/display labels, the existing badge/stage/effective expiry/source, an already-read observation timestamp when available, and its authoritative provider-management URL. No credential ID, event marker, raw document or remote-access status is projected. Use those same rows in Needs attention and Credential expiry, independently of notice dismissal or shared Skip/Return. No second expiry calculation or new persisted state is permitted.

The Settings owner supplied `RAN/Dashboard.php` integration equivalent to seven additions/one deletion: an optional reference to the existing container-bound notice plus one cached-summary payload assignment. Overview may apply that exact hunk for standalone proof; Settings remains sole shared composition writer. No Booster or service-provider change is needed. Keep storage-summary argument 7 and provider-facts argument 8 unchanged, and preserve this expiry payload through storage relocation. The existing observation read may carry its provider-check timestamp into its already computed status; this adds no observation read.

Projected added production cost before edits: CredentialExpiryNotice 40 lines, CredentialExpiryReminder 8 lines (including type documentation and the existing observation timestamp), approved Dashboard hunk 7 additions/1 deletion, onboarding view 10 lines, dashboard partial 25 lines. Zero new concrete production types, public extension seams, tables, options, JavaScript, polling or remote calls. Rejected larger alternatives: a new inventory/cache service, DTO, expiry engine or persisted history.
