RAN Booster Multisite recovery

RAN Booster 0.1 does not support WordPress Multisite. If an existing single-site installation is converted or restored as a network while Booster is active, Booster enters a safety mode. Managed package controls, deployments, webhooks and add-ons remain unavailable.

Before recovery

Create and verify a complete backup of:

  • the WordPress database;
  • wp-config.php and the WordPress installation;
  • the private encrypted Booster secrets file and its directory; and
  • the infrastructure needed to restore the site.

Do not delete Booster tables, the ran_booster_secrets_key_v1 option, the encrypted secrets file, or its locks as a workaround. These pieces authenticate one another. Partial deletion can prevent safe recovery or removal.

Recommended recovery

  1. Use WordPress Network Plugins to deactivate RAN Booster network-wide.
  2. Either leave Booster disabled or restore an already-supported single-site snapshot.
  3. Confirm the database, configuration, private Booster storage and installed package files match the backup.
  4. After returning to single-site WordPress, reactivate Booster and review Troubleshooting and every package before resuming Automatic operation.

If a future Booster release explicitly supports Multisite, follow that release's migration instructions. An available update or this Network Admin warning does not by itself mean Multisite is supported.

Updating Booster itself

Safety mode retains only Booster's isolated manual WordPress update route. Use the native WordPress Updates screen to check for a newer Booster release. Managed plugins and themes are not checked, installed or reinstalled in this mode.

Deliberate removal

After verifying the backup, deactivate Booster network-wide and use WordPress's normal Delete action only if all preserved Core state should be removed permanently. Uninstall authenticates and removes only the exact Core-owned key, encrypted sidecar, locks, schedules, options and tables. It does not scan every subsite or remove add-on-owned data.

If ownership is incomplete or ambiguous, uninstall stops and WordPress retains the plugin files. Restore the missing material from backup or return to single-site WordPress before trying again. Do not manually delete whichever piece remains.
